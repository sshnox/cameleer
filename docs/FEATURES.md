# Cameleer feature matrix

This page compares Cameleer with [Apache Camel 4](https://camel.apache.org/). It was written
by reading the code and the conformance test suite (`crates/cameleer-core/tests/conformance_*.rs`,
`crates/cameleer-http/tests/conformance_http.rs`), not from the wishlist.

Legend: ✅ implemented, ⚠️ partial (see notes), ❌ not implemented.

Cameleer uses only the Rust standard library, so anything that needs a database driver,
a broker client or a JVM library is out of scope unless it can be written from scratch. TLS is
provided by the from-scratch `cameleer-tls` crate and is wired into every network component
(see "TLS / SSL context parameters" below).

## Interop verified against real servers

Besides the embedded test servers, these components are verified end-to-end against real,
independent server software by the opt-in live suite (`CAMEL_LIVE_INTEROP=1`, servers set up by
`scripts/live-interop.sh`); details, broker limitations and the bugs it found are in
[INTEROP.md](INTEROP.md). The emulator-only areas (embedded Kafka broker and datastores, the
AWS / Azure / GCP mocks, the Azure flavour of the AMQP 1.0 broker) and the TLS, HTTP/2 and gRPC
stacks are additionally driven by officially published clients (librdkafka, pymongo, the
DataStax driver, elasticsearch-py, redis-py, boto3, the Azure SDK for Python, gcloud / gsutil /
bq, grpcio, Go's crypto/tls and net/http) in the opt-in `CAMEL_OFFICIAL_CLIENTS=1` suite
(`scripts/official-clients.sh`); see "Official clients" in [INTEROP.md](INTEROP.md).

## Core concepts

| Feature | Status | Notes |
|---|---|---|
| CamelContext lifecycle (start/stop/restart) | ✅ | Routes start by `startupOrder` and stop in reverse order. Default shutdown timeout is 45 s (`set_shutdown_timeout`). |
| Graceful shutdown | ✅ | Waits for in-flight exchanges. Exchanges still queued on a seda consumer are completed first unless `purgeWhenStopping=true`. |
| Adding/removing routes at runtime | ✅ | Routes added after start begin at once. `remove_route` returns `false` until the route is stopped, as in Camel. |
| Route ids, auto-generated ids (`route1`...) | ✅ | |
| `autoStartup`, `startupOrder`, route groups/descriptions | ✅ | |
| Suspend/resume | ✅ | `SuspendableService` (`Service::as_suspendable`): the seda, timer, scheduler, file, cron/quartz and platform-http consumers are suspended in place — seda leaves messages queued, timer/scheduler/cron skip fires, the file consumer skips polls, HTTP answers `503 Service Unavailable` — and in-flight exchanges complete; other consumers are stopped (as Camel does for non-suspendable consumers). `suspend_route`/`resume_route` (`start_route` resumes a suspended route), context-level `suspend()`/`resume()`, `RouteSuspended`/`RouteResumed`/`ContextSuspended`/`ContextResumed` events, `is_route_suspended_in_place`. |
| Exchange / Message / headers | ✅ | Headers are case-insensitive and keep the original key spelling. |
| Exchange patterns InOnly/InOut, `inOnly()`/`inOut()`/`setExchangePattern` | ✅ | |
| Exchange properties, variables (`setVariable`, `${variable.x}`) | ✅ | Variables are stored as exchange properties (`CamelVariable.<name>`), not in a separate variable repository. |
| `Exchange.correlated_copy` (`CamelCorrelationId`) | ✅ | |
| Type conversion (`convertBodyTo`, `bodyAs`) | ✅ | `cameleer_core::typeconverter`: a per-context `TypeConverterRegistry` (`ctx.type_converter()`) used by `convertBodyTo`/`convertHeaderTo`, Simple `bodyAs`/`headerAs`/`mandatoryBodyAs` and languages' `resultType`. Custom converters per (from, to) type (`add_converter`, `Object` = any source), fallback converters, `TypeConverterExists` policy (Override/Ignore/Fail), statistics (attempts/hits/misses/failures). Built-in conversions modelled on Camel's core converters: String (charset from `CamelCharsetName`), Character, Integer/Short/Byte (range checked), Long/BigInteger, Double/Float/BigDecimal/Number, Boolean, byte[]/InputStream/ByteBuffer, Map (JSON, `Properties` text), List/Collection/Iterator/Set/Object[]/String[], Date/Timestamp/Calendar (epoch millis), Instant/OffsetDateTime/ZonedDateTime/LocalDate/LocalDateTime/LocalTime, Duration (ISO-8601 or `1m30s`), UUID, URI/URL/File/Path, Reader/XML Document/Source (text), JsonNode. Values stay dynamic `Value`s, so a "type" is a name (`com.acme.Order` keys custom converters). |
| Unit of work, on-completion synchronizations | ✅ | `useOriginalMessage` follows Camel's unit-of-work scope: it spans direct/seda routes, and split/multicast/recipientList start a child unit of work unless `shareUnitOfWork`. |
| Property placeholders `{{key}}`, `{{key:default}}`, `{{env:X}}` | ✅ | Resolved in uris, endpoint options and Simple expressions when the route is created. |
| Registry / beans | ✅ | A typed registry (`bind`, `lookup`, processors, aggregation strategies, bean methods). |
| Event notifiers | ✅ | Context, route and exchange events. |
| Endpoint uri normalization | ✅ | Like Camel's `URISupport.normalizeUri`: `Endpoint::uri()`, route endpoints, `CamelToEndpoint`, `CamelRecipientListEndpoint`, `CamelSlipEndpoint`, `CamelFailureEndpoint`, `CamelInterceptedEndpoint` and endpoint errors use `scheme://path?sorted-params` (`mock://result`, `seda://foo?blockWhenFull=true&size=10`, values encoded like `URLEncoder`). Lookups and `interceptSendToEndpoint` patterns work with either form. `RAW(...)` values are shown encoded rather than as `RAW(...)`. |
| Value predicate truthiness | ✅ | `ObjectHelper.evaluateValuePredicate` (`Value::is_predicate_true`): a boolean is its value, a string is false only for `"false"` (trimmed, any case), an array is true when not empty, null is false and anything else (`0`, `""`, maps, bytes) is true. Used by Simple, `header`/`constant`/... languages used as predicates and JSONPath. |
| SSL context parameters (`SSLContextParameters`) | ✅ | `cameleer_tls::SslContextParameters`: key and trust stores as PEM (combined or separate certificate/key files, `ENCRYPTED PRIVATE KEY` with PBES2 or PKCS#12 PBE), PKCS#12 (`.p12`/`.pfx`: PBES2/PBKDF2-HMAC-SHA1/256 + AES-128/256-CBC, legacy 3DES and RC2-40, HMAC-SHA1/256 MAC), Java JKS and JCEKS (format detected or `keyStoreType`/`trustStoreType`; `keystorePassword`, `keyPassword`, `certAlias`, `trustStorePassword`), optional system trust store, `insecure_skip_verify`, host name verification switch, ALPN, min/max TLS version, SNI override, client authentication (`clientAuthentication=NONE\|WANT\|REQUIRE`, also `serverParameters.clientAuthentication`; the client presents its key store when asked), CRL files (`crlFile`), session resumption (`sessionResumption`, `sessionTimeout`). Bind as a bean and reference with `sslContextParameters=#name` (also `camel.component.<scheme>.sslContextParameters`), or configure the global parameters with `camel.ssl.*` properties (`camel.ssl.enabled=true`, `keyStore`/`certFile`+`keyFile`, `keystorePassword`, `keyPassword`, `keyStoreType`, `certAlias`, `trustStore`, `trustStorePassword`, `trustStoreType`, `trustAllCertificates`, `hostnameVerification`, `secureSocketProtocol(s)`, `clientAuthentication`, `crlFile`, `sessionTimeout`) or the bean `CamelGlobalSSLContextParameters`, used with `useGlobalSslContextParameters=true` and as the default trust for TLS endpoints when `camel.ssl.enabled=true`. Embedded HTTP server: `camel.server.ssl.*` / `camel.server.sslEnabled` / `camel.server.useGlobalSslContextParameters`. TLS failures are `SSLHandshakeException`/`SSLPeerUnverifiedException` (subclasses of `IOException`). Not supported: OCSP, JCEKS secret-key entries, PKCS#12 public-key integrity/privacy modes, key managers selecting among several key entries by SNI. |

## Error handling

| Feature | Status | Notes |
|---|---|---|
| DefaultErrorHandler, DeadLetterChannel, NoErrorHandler | ✅ | Redelivery headers `CamelRedelivered`, `CamelRedeliveryCounter` and `CamelRedeliveryMaxCounter`. Redelivery happens at the point of failure. |
| Redelivery policy (delay, back-off, collision avoidance, delayPattern, max delay, retryWhile, onRedelivery, onExceptionOccurred, onPrepareFailure, log levels, asyncDelayedRedelivery) | ✅ | With `asyncDelayedRedelivery` (Rust DSL and YAML `redeliveryPolicy`) the consumer thread of asynchronous consumers (seda, timer) is released during the delay: a replacement consumer thread takes over and the waiting exchange finishes on the released thread (Cameleer processors are synchronous, so this is a thread hand-off rather than a scheduler continuation). | Error handler scope across direct sub-routes | ✅ | The failing route's error handler applies. A handled exchange stops the caller too (`CamelErrorHandlerHandled`). An exhausted exchange is not redelivered again by the caller. |
| deadLetterHandleNewException | ✅ | |
| doTry / doCatch (onWhen) / doFinally | ✅ | No error-handler redelivery inside doTry. |
| onCompletion (onCompleteOnly, onFailureOnly, onWhen, mode before/after consumer, route/global scope) | ✅ | |
| ProducerTemplate failures | ✅ | Returned as `CamelExecutionException` with the original exception as the cause. |

## Known deviations found by the conformance suite

These differences are kept on purpose (documented, not fixed):

1. In Simple text, `$${` is an escape that produces a literal `${`.
2. TLS comes from the in-house `cameleer-tls` crate (unaudited; see its limitations), not a mature library.
3. Asynchronous delays (`asyncDelayed`, `asyncDelayedRedelivery`) hand the waiting exchange to its (released) thread and start a replacement consumer thread, instead of scheduling a continuation on a scheduler pool.
